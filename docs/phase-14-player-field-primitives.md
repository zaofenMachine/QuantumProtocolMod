# 第十四阶段：玩家场上恢复原语

日期：2026-09-09

版本：v0.15.0-dev（研究探针）

状态：同一场内精确换格，以及抑制出牌效果的手牌到精确场格再回手牌，均已实机通过。正式玩家场面补充尚未接入路线 C。

## 已验证的场内换格

游戏私有 `Action_MoveCardOnField` 队列入口位于 RVA `0xE35CF0`，构造函数位于 `0xDFB160`，执行函数位于 `0xE43160`。`CardPlacement` 的受保护原生布局为 12 字节：类型 `+0x0`、索引 `+0x4`、行 `+0x8`、阵营 `+0x9`。

同一张 `naturalCherry` 在两轮独立探针中均按以下路径完成：

- `PLAYER:BACK:0 → PLAYER:BACK:1 → PLAYER:BACK:0`；
- 每轮在目标格停留约 1200 ms；
- 卡牌 UObject、共享状态指针和 GUID 全程不变；
- 使用空格、零队列模式、不挤占已有卡、不启用自动寻找后备格。

玩家观察到界面中的 `(2,1)` 卡移动到 `(2,2)` 后再回到 `(2,1)`，与原生位置读回一致。

## 被否定的通用 FIELD 目的地

`Action_MoveCard` 能可靠处理 `HAND/DECK/TRASH`，但其目的地 `FIELD=3` 分支只从来源控制器移除卡牌，不负责把卡牌插入场地。以 `spStorageHit` 测试时，权威位置既未成为 FIELD，也未恢复为 HAND，动作队列等待超时，用户看到画面卡住。

该路径已经从探针移除，不能用于正式恢复。失败样本证明不能把通用位置枚举中存在 `FIELD` 解释为完整的跨区落位能力。

## 抑制效果的正式落位动作

真正的 `Action_PlayCardToFieldResolve` 队列入口位于 RVA `0xE37F10`，构造函数位于 `0xDFBA80`，执行函数位于 `0xE441D0`。它会把 HAND 卡加入给定的精确空场格，但执行末尾会无条件调用 RVA `0xE383C0` 派发卡牌的出牌效果。

反汇编确认派发函数只遍历卡牌原生对象的效果数组：指针 `+0x1B8`、数量 `+0x1C0`、容量 `+0x1C4`。受保护探针因此采用以下事务：

1. 只允许 `naturalApple`、`naturalLemon`、`naturalSpring` 普通水果；
2. 校验 EXE 指纹、四个原生函数签名、卡牌共享引用、效果数组头和每个效果引用；
3. 暂时把效果数量写为 0，再把原生 PlayCard 动作排入精确空格；
4. 一旦权威位置变为 FIELD，立即校验并恢复原指针、数量和容量；
5. 停留 1200 ms 后，通过已验证的通用 MoveCard 动作返回 HAND。

最终样本选择 `naturalApple`，从 HAND 精确进入 `PLAYER:FRONT:0`。原效果数量为 1，落位后在同一更新周期恢复；实际停留 1201 ms，随后回到 HAND。结构化报告为 `passed`，用户确认画面动作与预期一致且没有触发苹果的入场效果。

## 安全结论与下一步

- 正式实现可以组合“固定顺序启动暂存 + 效果抑制 PlayCard + MoveCardOnField + 既有生命/回合写回”恢复玩家场上卡。
- 首版应只处理玩家场上卡，要求目标格为空、无 PENDING 卡，并逐张串行排队；不能同时扩张敌方场面。
- 效果数组只能在单个 PlayCard 动作窗口内临时抑制，恢复前后必须校验指针、数量和容量；任何不一致都应中止精确层。
- 通用 MoveCard 的 FIELD 目的地永久列为禁用路径。
