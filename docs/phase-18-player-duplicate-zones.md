# 第十八阶段：跨玩家牌区的同名副本

日期：2026-09-13（Asia/Shanghai）。版本：v0.19.0。

## 问题与实现

原生有序对象计划已经能区分“应留在手牌/牌库的副本”和“暂存后要搬走的副本”。此前仍保留的跨手/场/墓同身份拒绝规则，会使“一张苹果在手，另一张在场”的普通局面无法精确恢复。

本阶段仅对玩家牌区 schema 2 中的苹果、柠檬和春放开跨目的牌区同身份分配。身份包含标签和升级等级。计划先按原生相对顺序占用必须留在牌库和手牌的对象，再为保存的墓地序列、场地格位逐一分配尚未使用的副本。场地生命和攻击状态始终跟随保存格位应用。共享身份不再意味着共享一个运行时目标。

独立墓地补充的保存验证同步允许这些普通水果在手牌和墓地各有副本。旧 schema 1 缺少原始顺序，继续保留原限制；其他特殊卡的跨手/场/墓同身份情况也继续拒绝。文件格式没有增加字段，沿用 schema 2。

## 验证

构建与 CTest 通过。离线覆盖手/场、手/墓、场/墓副本分配，以及五份同身份副本同时分布于牌库、手牌、墓地和两个场格的唯一分配。不同升级不能代替缺失副本，特殊卡和旧格式的限制仍生效。

实机样本从第十七阶段的合法非排序牌库/手牌检查点通过普通出牌和执行生成，未编辑检查点卡牌负载。三个组合均以两张苹果为例：先将一张放入后排格 0，保留另一张在手牌；执行后排后得到手牌和墓地各一张；再将手牌苹果放入后排格 4，得到场地与墓地各一张。

## 仍有的边界

牌库和手牌仍要求非空，PENDING 为空。支持的场地状态仍为格位、生命及攻击状态；更多卡牌计数器、动态效果、满充能和空牌区将继续逐项处理。重编程重开与敌人精确恢复保持搁置。
