# 第三十七阶段：牌库／墓地基础生命与稳定捕获

> 2026-09-30，v0.38.0。本阶段受限验收及证据封存已完成。方向仍为“小关重开＋玩家精确恢复”，重编程及敌人精确恢复继续搁置。

## 本阶段解决的问题

焰火正常回手后基础生命可从 1 增长到 2；这个变化随后经露西娅弃牌进入 TRASH，或经奥瑞莉娅洗回 DECK，旧版只支持 HAND 的门禁会拒绝该状态。新布局直接按各区完整 CardInfo 与原生下标保存基础生命，不能按卡名合并同名副本。

Z5、T6、F9 分别增加 `playerDeckBaseHealthStates`，及适用布局中的 `playerTrashBaseHealthStates`。HAND3 保持独立。D/T 只接受相对选中定义的非负基础生命增长，要求 base=current=max、没有 HEALTH 修正或独立上限调整，并继续遵守攻击、LEVEL、计数器、回合和技能成员门禁。新字段进入已有布局校验和；旧 schema 的校验和顺序保持原样，旧 JSON 偷带新字段也会被拒绝。

恢复先完成全部布局及 MOVE 释放，然后顺序恢复 D/T 基础生命，再进入 HAND 基础生命、HEALTH 修正和计数器。所有目标在首次数值写入前按定义、位置和新建原生状态预检；原生 SET_BASE_STATS 仅设置 HEALTH。终验和稳定窗口只读，漂移会触发一次普通 Route C 回退，不重复修补数值。

外部验收新增原生索引绑定的 D/T HP 缓存检查，以及报告／trace 的同步顺序、次数和目标核对。`nativeHealth:` 与 `nativeEffects:` 两个导出前缀读的是同一组物理偏移 `0x29C/0x2A0`，不是四份独立测量，也不代表全部 UI 或私有历史已经恢复。

## 保存时的原生队列与自动重试

保存读取前、发布新主文件／失效旧补充前都要求原生动作树完成且延迟队列为空。最终恢复稳定窗口遇到合法 busy 会重新计时。DEV 真实 +1 generic 动作已经验证 OPEN 不代表队列安定：手动保存拒绝时原 7 文件不变，正常 resume 后同一张苹果计数变为 1。

自动捕获原先在调用保存前就清掉 pending，遇到临时 busy 会漏掉该波次。最终候选将两处写入前的 native busy 区分为专门异常；普通 PROCESSING 且无选牌／放置提示时，只在读取前允许另一个专门等待分支。两者分别计数，每 500 ms 重试，首次到期后最多 30 秒；同波重复调度不能延长期限或重新绑定已失效的对象。CHOOSE、SYSTEM_PAUSE、未知状态、提示、场景变化、结构及 IO 错误仍终止，写入前由 OPEN 变为其他状态也终止；手动保存仍即时拒绝不稳定状态。

延期要求世界与引擎的有效 weak serial，以及 spawner 的 weak serial 或公开 SDK 单目标删除监听见证。全局删除 epoch 只保护最初绑定区间，之后固定的 target epoch 仅因目标 spawner 删除、监视目标替换或关闭而失效；同时持续核对引擎权威引用、对象索引／名称、波次和关卡。回调只比较原子地址和递增 epoch，不解引用对象。此实现要求关闭 UE4SS 热重载，替换 DLL 前先退出游戏，不承诺运行中卸载或 GC 锁保护。首次原有 1.5 秒延迟捕获保留无完整见证的兼容域，报告与延期身份明确区分。

候选源码 `FA087724…`，生产配置 `CDEA661D…`，DEV `2B4387A1…`，ON/OFF 各 4/4 CTest；生产已检查测试标记不存在。`2B4387A1…` 实际因 spawner 没有现成 weak serial 在原生入队前拒绝，不能计作自动重试通过。后续 DEV `10ABAD83…` 使用公开 SDK 删除监听和全局删除 epoch，已真实排入 +1 动作并保留 busy 请求、保持原 7 文件不变；resume 后第二次尝试因 epoch 改变取消，没有自动保存成功。日志没有记录被删对象，不能断言其具体来源；全局任意对象删除使该见证过于保守，单目标见证仍在处理。
