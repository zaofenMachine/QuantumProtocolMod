# 第三十一阶段：生成卡退场后的空场恢复

日期：2026-09-13（Asia/Shanghai）。版本：v0.32.0。

## 补齐实际退场流程

上一阶段的额外苹果只能通过非空 FIELD 补充恢复。继续让生成苹果和春正常执行退场，得到牌库 0、手牌 6、墓地 3、场地 0 的真实状态，总数仍为 9。v0.31.0 的墓地补充因原牌组只有 8 张而拒绝捕获；FIELD 因为空也无法承担恢复。

墓地 schema 3 现在采用同一套单苹果扩展：必须保留原始完整多重集合，仅允许原牌组含苹果和春时多一张未升级苹果。原生墓地顺序、空牌库／空手牌、手牌暂存继续沿用已有实现；schema 1 和 2 保留可读性及原有严格集合规则。schema 版本参与校验和，旧补充不会被当作新策略使用。

场外默认属性校验提取为共用函数。生成卡扩展捕获仍拒绝场外属性修正、非默认生命及计数器；不把这些未保存的状态默认为已经恢复。启动后的生命上限和牌组决定的倒计时归一化，现在接受已完成的 FIELD schema 6 或墓地 schema 3，仍需通过全部原生对象、函数、边界和跨帧检查。普通无副本恢复不执行归一化。

## 验证

真实空场样本的手牌、墓地顺序、卡牌身份、生命、攻击、等级、计数器、角色资源和回合状态恢复一致，再次保存保持战斗 9 张／永久牌组 8 张。此样本没有上一阶段春在场时的 INIT 完成显示历史差异。

点击空牌库后未产生新卡，游戏继续结算一个回合，抽牌倒计时由 0 变为 5。对照组先通过实际退场形成同样空场，再执行相同点击；与恢复组的玩家状态逐项比较，确认这一行为并非恢复卡死或额外副本丢失。敌方状态仍按小关重开处理。

正式构建关闭开发夹具。最终回归覆盖新进程空场恢复、再保存后的空场、旧 schema 2 原生墓地及既有 schema 6 生成苹果场地；旧墓地基线缺少等级观测，新增等级比较明确保持未知，其他已覆盖字段全部验证。四个 CTest 目标通过。最早的 schema 1 原始检查点另行恢复并原样保留。
