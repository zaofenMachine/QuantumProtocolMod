# 检查点 Mod 需求基线

状态：路线 C v1 已通过；可选精确层已恢复未来 `spawnList` 和纯净小关开头牌区，复杂样本的 5/8 当前生命也已通过。已有玩家场上/墓地、特殊资源、战斗回合及敌方运行状态仍待处理。

## 产品目标

为《Quantum Protocol》增加一个局内检查点。玩家死亡后，或在退出游戏并重新启动后，可以选择从最近一次有效检查点继续，而不是丢失整段进度。

检查点只有一个槽位。新检查点自动覆盖旧检查点，并以独立文件持久化；不能只存在于当前游戏进程的内存中。

## 路线 C v1 验收语义

路线 C 的目的不是复原保存画面，而是用保存时的流程数据重新开始同一个普通小关：

- 保存文件在正常返回菜单、正常退出和重新启动游戏后仍存在。
- 下次启动后可通过安全热键读取；稳定后再设计 UI。
- 恢复保存的角色、关卡上下文、活动牌组、缓存区、波次索引和玩家生命。
- 敌人由关卡原生 `spawnWaveIndex` 重新生成；玩家牌区由原生重载流程重新洗牌并抽牌。
- 不要求保持原手牌、牌库顺序、玩家场上/墓地、敌人生命/效果或随机数状态。
- 保存并恢复玩家保存时的当前生命值；恢复时不得突破当前有效上限。
- 只在动作队列已结算、对象状态稳定时写入检查点，避免保存半个动画或半个效果。
- 对存档做版本标记、完整性检查和原子写入；损坏或版本不兼容时拒绝载入，不修改游戏原生 `.sav`。
- 游戏 EXE 不匹配、模式或 Spawner 超出白名单、教程/Boss 伴生对象存在、数据损坏时必须拒绝。
- 恢复事务必须有超时、动作队列恢复和结构化结果报告；失败不能被宣称为成功。

首版只支持 `ELEVEL_TYPE::DUNGEON` 的普通战斗。明确排除 `DUNGEON_EVENT`、`INFINITE`、教程、Boss 伴生逻辑、带独立状态的特殊 Spawner，以及死亡界面的一键恢复。

## 候选方向 A：精确小关快照

在每一小关开始且初始生成完成后自动覆盖检查点。读取时恢复到该小关开头。

如果这条路线要求“精确回到保存画面”，则需要保存并重建玩家：

- 手牌及其顺序。
- 牌库内容、顺序和所有升级。
- 缓存区/储存区的完整内容、升级和顺序。
- 场上卡牌的位置、升级、当前数值、回合计数、效果和临时修改。
- 墓地、待处理区和移出游戏集合。

敌人原则上可以让该小关的原生生成流程重新建立；若保存点不是纯净的小关边界，仍需精确保存敌方状态。

## 候选方向 B：“重编程”后的敌人精确恢复

玩家使用“重编程”，完成局内卡组编辑，并由游戏重载玩家牌区、重新洗牌和抽出五张牌后，自动覆盖唯一检查点。

### 玩家卡牌

必须保存：

- 编辑完成后的完整卡组构成。
- 每张卡的升级级别及其他永久卡片属性。
- 缓存区/储存区的完整构成、升级和顺序。

不要求保存：

- 当时手牌的具体五张牌。
- 牌库的精确随机顺序。
- 玩家场上、墓地和待处理区在按下重编程前的状态。

读取时采用游戏原生“重编程重开”语义：使用保存的卡组与缓存区重建玩家牌区，重新洗牌并抽五张。因而读取结果不保证与保存瞬间的五张手牌相同。

### 敌人

敌人必须精确恢复到保存瞬间，至少包括：

- 场上、待处理区和墓地中的所有敌方卡牌。
- 卡牌标识、实例身份所需数据、升级和场上位置。
- 当前生命、回合计数和其他卡牌计数器。
- 持续效果、状态、临时属性修改及其剩余时间。
- 当前小关、波次索引、生成倒计时及会影响后续生成的控制器状态。

仅重新调用该波次的生成函数不符合“精确恢复”要求。

## 暂不作为硬性目标

- 还原完全相同的随机数发生器状态。
- 让重编程路线得到与保存瞬间完全相同的五张手牌或牌库顺序。
- 多个手动存档槽。
- 修改或替代游戏的原生永久存档。

## 路线 C 通过后的决定

路线 C 保留为稳定恢复底座，不把现有 schema 2 和已通过事务直接改造成一次性全量精确快照。精确恢复先增加独立的只读状态签名与恢复后差异报告，再依据真实差异选择最小、可验证、可回滚的写回切片。

首份差异报告确认重载会同时改变玩家手牌/牌库和未来小关顺序。未来 `spawnList` 已通过与主检查点校验和绑定的独立补充文件恢复，并在失败时安全降级；后续精确字段继续沿用这一可选分层，不提升路线 C 主 schema 的耦合度。

第二个补充文件使用原生 `FDecklist.fixedOrder` 恢复牌库/手牌，只在两区卡牌合计与活动牌组的标签、升级和数量完全一致时启用；否则不建立该补充。它不改变路线 C 对中途场上、墓地、待处理区和敌人伤势的非精确边界。

以下产品问题仍待决定：

- 唯一检查点在通关、放弃流程、新开流程或游戏版本升级后何时删除。
- 除生命外，还有哪些玩家资源需要精确保存。
- 缓存区是否存在必须保持的隐藏顺序或实例身份。
- 读取入口的最终 UI 位置，以及死亡界面是否直接提供“从检查点重试”。
- 特殊卡组、特殊关卡和剧情战是否允许建立检查点。
- 精确恢复若继续，应优先扩展路线 C 的玩家状态，还是改走重编程锚点的敌人重建。
