# 第三十六阶段：手牌基础生命与生命修正联合恢复

日期：2026-09-20。版本 v0.37.0，本轮实机验收已完成；提交与远端核验记录见本阶段 `validation-summary.json`。上一份生产版本为 [v0.36.0](phase-35-player-effect-membership-guards.md)。方向继续为小关重开与玩家精确恢复，重编程重开与敌人精确恢复保持搁置。

## 范围与依据

HAND schema 3 沿用已有的基础生命、最大生命、HEALTH 修正与普通计数记录。只允许基础生命相对所选不可变定义的非负增长，并保留正数、有界、当前生命等于最大生命、无独立最大生命调整、非负 HEALTH 修正，以及默认攻击、等级、回合状态等门禁。DECK/TRASH 仍要求定义基础值；FIELD 捕获也明确拒绝基础生命偏离其所选定义。

旧 HAND 1/2 必须保持定义基础生命，不会因新版解析器支持 schema 3 而扩大含义。HAND 3 还要求实际选用的布局具有保存时技能成员证明，即 zones 4 / trash 5 / field 8；不新增布局版本。旧版固定校验和与字段规则保持不变。

正常 UI 操作已复现焰火 `mageSorcIgnis` 基础生命 1 → 上升涡流回手后 2 → 奥克塔娃添加 HEALTH +1 后最大生命 3。再次正常打出焰火时，其自身 INIT 将基础生命及当前生命重置为 1，并清除 HEALTH 修正。七份 v0.36.0 清单确认同一卡的 GUID、原生对象、完整 CardInfo 与有序技能成员保持一致；两次旧版保存正确拒绝不支持的动态基础生命。动作历史变化原样保留，不归一化为相等。

## 写回顺序

原生 SET_BASE_STATS HEALTH 动作为绝对值写入，同时设置当前生命并清除 HEALTH 修正。因此先完成所有布局与临时搬牌，再验证每张手牌均处于定义基础值、无修正的全新状态，然后依次恢复所有基础生命、所有 HEALTH 修正、普通计数。

每一步只接受写入前或预期写入后状态；卡牌对象、原生状态与手牌索引保持绑定。观察到第三种状态或最终稳定窗口发生漂移时，沿用一次普通 Route C 回退，不能再次入队数值来修补漂移。报告新增 `exactPlayerHandBaseHealthActionsQueued`。

## 已修复的恢复搬牌问题

第一次 v0.37.0 实机恢复旧 HAND 2 默认焰火存档时失败，且正确执行了一次普通回退。原因是恢复暂存过程中的 DECK → HAND 原生 MOVE 触发焰火自己的回手成长，导致基础生命从 1 变为 2；新鲜状态门禁拒绝后，基础生命写回动作数为 0。该失败证据不会计入成功样本。

修复采用仅用于恢复路径的逐目标临时技能列表数量抑制，覆盖手牌暂存、独立墓地批次及其回滚、场地恢复所需搬牌。临时抑制结束必须同时满足引擎 OPEN、动作树已完成、延迟队列空、目标到达预期区域。游戏会保留已完成动作，因此数组长度不能代表待处理动作数。整批恢复原技能数量后才重新验证成员，异常清理独立于定义验证。

该措施只抑制被搬动目标自身的效果，不是全场技能或历史隔离。其他卡监听搬牌引起的状态变化仍由现有严格状态检查拒绝。`restoreMoveEffectsSuppressed/Restored/Pending` 用于验证临时抑制的对称释放。修复后的旧 HAND 2 默认样本已通过，基础生命动作 0、抑制/释放 10/10、pending 0；自然成长 HAND 3 的同进程与重存后新进程样本也通过，基础生命动作各为 1，所有玩家原生状态比较一致。

另一份联合生命样本中，敌方蓝病毒在奥克塔娃执行后删除了它的三个技能。保存门禁正确拒绝全部玩家、充能和回合精确补充，只保留普通主文件与有效刷怪计划。此样本作为拒绝案例保留，不计作联合恢复成功。

## 联合样本发现的显示同步缺口

使用不含蓝病毒的来源重新生成 base 2 + HEALTH 1 联合样本后，运行时恢复报告通过，trace 确认基础生命写回先于 HEALTH 修正。但独立比较发现 TRASH 上升涡流的原生技能仍为 1，UI 技能列表却为 0，导致完整原生顺序状态的可用性检查失败。重存再次恢复仍有同一缺口，不能将它归一化成已知动作历史差异，也不能把 unknown 当作 true。

已确认游戏自身的 `FB94F0` 是正常 card Tick 使用的技能显示同步函数：保留 GUID 匹配的现有显示实例，仅补缺项，并会触发普通粒子与音效，不派发卡牌技能动作。修复限定于 MOVE 整批正常释放之后；异常清理仍只还原原生数量。第一版有序前缀补缺已使 DEV 联合样本通过全部 25 项玩家比较，但生产旧混合 FIELD 回归发现 Flashbang 留下的显示不是原生技能的有序前缀，恢复安全回退，抑制/释放 9/9、pending 0。

最终修复先验证现存显示是原生技能的唯一合法子集，原生补齐后保留所有旧 actor/widget/history，只对 UI 指针数组做原地排列，再由原生函数同步位置。不写数组 header，不增删原生技能或共享引用；最终比较与稳定窗口仍严格要求完整、有序。生产样本 `final2-legacy-hand2-mixed-field` 直接记录 Flashbang 序号 `[1] → [1,0] → [0,1]`，全部 25 项玩家比较通过。日志只记录序号和保留数，实例与历史保持由指定 DLL 的调用前后门禁验证，不将序号日志夸称为私有历史快照。

另外修正比较脚本的一处范围错误：`playerZoneSequencesEqual` 之前比较了含敌人区域的整个 map。现改为只比较 `/PLAYER`，完整敌方区域差异仍保留在原始 differences 和 semanticEqual 中。没有放宽缺失 UI 时的 ordered-state 可用性判断；原失败比较与验证文件另存保留。
