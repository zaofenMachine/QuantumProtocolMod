# 第二十一阶段：恢复对象扫描优化

日期：2026-09-13（Asia/Shanghai）。版本：v0.22.0。

## 问题与修改

恢复期间每次查找控制器、牌区和卡牌都会遍历全部 UObject，并先生成完整对象名称。场地稳定性校验会多次调用这些路径，明显拖慢游戏线程。

现在只缓存原生 UClass 元数据，在生成名称前通过 IsA 排除无关对象。查找目标仍经过原名称、关卡、存活状态、CardEngine 所属关系、共享引用和原生数组成员校验，没有缓存跨关卡的实例。类型元数据找不到时保留原完整扫描路径。恢复报告新增 `nativeObjectTypeFiltersActive`。

只读导出另加入 HUD 悬停信息 getter 和属性修正相关函数地址，供下一阶段定位动态状态。当前样本的 HUD getter 仍返回默认结构，不能用于证明任意卡牌的攻击力；未调用 HUD setter 或卡牌视觉 setter，也未将显示缓存加入精确恢复承诺。

## 实机验证

同一个“七张手牌、场上一张苹果、最后一张手牌也是苹果”样本，从新进程恢复成功，完整已采集玩家状态、原生顺序、实例和场格一致。v0.21.0 的完整场地校验平均间隔为 617.4 ms，v0.22.0 为 104.46 ms；三秒稳定窗口内分别记录 6 次和 29 次校验。这是两轮对应样本的日志间隔，不能等同于渲染 FPS 或严谨性能基准。

混合场地／墓地、全墓地和旧 schema 1 场地回归通过。正式无夹具 DLL 下共四轮 requested 恢复、三份独立已观测玩家状态比较通过；所有恢复均启用了类型筛选。

在满手牌场地样本的最终稳定窗口内，实际拖动手牌改变顺序。`225835-434` 检测到场地组合的最终验证失配，随后 `225845-519` 完成一次 semantic-fallback。这补上了此前未实际生效的场地组合顺序干扰样本。

构建和 CTest 通过。证据目录：`QuantumProtoclMod.runtime-evidence/20260913-player-state-observation`，具体报告、比较项、时间数据和源码散列见 `validation-summary.json`。原检查点已保留。
